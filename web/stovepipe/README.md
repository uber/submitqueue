# Stovepipe web UI

A read-only, framework-neutral React UI with a queue request list and an exact change page containing project status and retained history. The host supplies configured queue/project lists and a structural `StovepipeService` client. It owns authentication, transport, logging and OpenTelemetry providers.

Use the server entry's `createStovepipeWeb` to load a page and render its model with `StovepipeApp`. Mount beneath `WebNavigationProvider` when the host supplies client navigation and refresh. Without it, links and refresh use ordinary document navigation. Import `@submitqueue/web-stovepipe/styles.css`.

Change pages use `/<queue>/change/<percent-escaped-uri>` and look up status with `GetProjectStatusByURI`; history uses the request ID returned by that lookup. The `/request/` path is reserved for a future ID-based view. Queue pagination uses the backend's opaque continuations. Project pagination selects ten configured project IDs per page. Project pages show up to ten selected projects beside the request status, with history beneath both sections. The raw JSON link returns only the projects array across all backend pages, independent of the displayed page; the reference host serializes each project as protobuf JSON. The latest URL has no time window. Refresh failures retain previous successful sections for the same route; changing requests clears them. History loads after status identifies the request. Project completeness and lifecycle labels come from the backend. Missing results remain distinct from recorded zero/green. Project IDs are selected by the host; this is not an inventory of every project in a repository.
